截圖與各 agent 的補拍在 `D:/Temp/claude/gambit-review-2026-11-17/`（repo 之外，暫存）。

這次重構屬於定位 v2 的目標 B（值得做的工程專案），不是目標 A（學棋）。排序因此以「下棋 → 棋憶 → 回到下棋」這條主迴圈為先。

工作量 S／M／L 是相對粗估，不是工時承諾。

## 1. 一句話診斷

色票、木盤、Neve 的文字都已經到位，規則也大多守住了。它還像半成品，是因為沒有一樣視覺語言被做到底：首頁最大的一塊是空的漸層，待最久的對局頁滿是點陣字，定位上最重要的棋憶整屏米白，同樣是「棋盤加一段話」的畫面做了五種長相。每一頁都是在不同時間各自定稿的，沒有人把全站橫著對過一次。

## 2. 根本原因（依影響排序）

### 原因一：畫面上沒有主體，世界觀只寫在文件裡

persona-neve.md 寫了「亙古的棋盤」「棋靈」，README 寫了「精緻木質殿堂」。畫面上除了棋盤和一顆頭像，沒有任何一張圖。氛圍全靠低透明度的漸層和很細的筆畫撐，淡到等於沒有。

- 首頁場景帶高 222px，內容只到 100px，下面 96px 是空的深青（mobile-01-home-fresh.png，標題底線以下到米白交界；NeveSceneHeader.vue:74、83-91）。早、午、晚三張截圖只差問候語兩個字。
- 登入頁是 logo、漸層、兩顆按鈕，中間空 224px，唯一一句話是英文「MASTER THE BOARD」（mobile-00-landing-gate.png；SignInView.vue:33）。
- Neve 在全站只有 32–40px。設計目錄裡其實有一張 1254px 的原圖（design/gambit-design-system/avatars/neve-main.png），README.md:13 還寫著尚無插畫。
- 空狀態、分析等待、404 各用各的範本（mobile-09-history-empty.png、mobile-10-review-analysing.png、mobile-12-not-found.png）。

影響：首頁、登入、棋憶等待態、所有空狀態。

### 原因二：畫面的重心和產品的重心相反

定位 v2 的一句話是「把你剛下完的那盤棋變成明天的題目」。打磨最完整的卻是課程完成卡和對局設定彈窗；下完一盤、回頭看那一盤，這兩個時刻最素。外框（頂欄、底部導覽、設定選單）是功能一路刪減後剩下的樣子，沒有重新設計過。

- 棋憶的說明格整屏米白，唯一的綠是棋盤下方 18×6px 的段點（mobile-10-review-ready-full.png）。它是全站唯一把木盤放在米白上的棋盤頁，也沒有全站頂欄。
- 完局時贏、輸、和是同一張卡，以 v-if 直接換上來，沒有進場（PlayView.vue:349-378；work-play/m-gameover-viewport.png）。課程完成卡反而有徽章、金線、墨點和 380ms 進場（work-learn/mobile-lesson-complete.png）。
- 下過四盤的首頁和全新首頁在 y=280 以下逐像素相同，兩張卡是「開始新對局」和「繼續學習」。上一盤的棋憶沒有入口；通往對局紀錄的連結全站只有一個，在齒輪選單裡（settings-menu.vue:45；mobile-13-settings-menu.png）。有未下完的對局時，第一張卡會換成「繼續對局」，其餘相同。
- 底部導覽是 358×58px 的膠囊，裡面兩個目的地。在對局、對局紀錄、404 三頁沒有任何一格亮著，只剩兩顆沒有字的圖示（mobile-02-play-board-midgame.png、mobile-09-history-games.png 底部；app-nav.vue:23-26）。

影響：首頁、棋憶、完局、對局紀錄，以及每一屏的底部導覽。

### 原因三：每一頁各自定稿，沒有共用的骨架

- 「棋盤加一段話」做了五次：對局、課程與深化、判斷場、練習、棋憶。返回鍵有四種；Neve 名牌有兩種寫法（課程是黑體「Neve」，棋憶與完局是點陣「NEVE」）；面板圓角 12／14／18。把 mobile-07-lesson.png、mobile-08-practice.png、mobile-10-review-ready-full.png、mobile-02-play-board-midgame.png 四張的頂列與下方面板並排看，像四個 app。
- 木框的同一串 class 原樣複製五份（PlayView.vue:328、LessonPlayer.vue:278、RecognitionBoard.vue:138、KeyMomentsCard.vue:232、PracticePuzzleView.vue:216）。
- 每個 view 自己寫 max-w（448／480／672／768／896／1024）。桌機 1440 寬下內容左緣有八種位置，棋盤有四種寬度（640／528／456／424）。只有對局和課程是設計過的雙欄，其餘是手機欄置中：desktop-10-review-ready-full.png 左右各空 496px，desktop-01-home-returning-h20.png 兩張卡以下 43% 是空的。
- Neve 的回饋各做各的。課程把她的回饋裝進表單式的彩色警示框並換成黑體（LessonPlayer.vue:365-390）；判斷場開場白直接壓在變暗的棋盤上，沒有頭像也沒有框（work-skeptic-dsys/judge-fork.png；RecognitionGate.vue:277-289）。

影響：五個棋盤頁、桌機全部頁面。

### 原因四：設計系統只長到顏色，而且只加不減

顏色幾乎都走 token。字級、圓角、陰影、間距、深青面的漸層、動效則靠就地手調，arbitrary value 共 280 處。裝飾是一輪輪樣張各自拍板後疊上去的，沒有最後一輪減法。

- 字級 21 種，設計文件只定 9 種；text-[11px] 18 處、text-[15px] 16 處。學習頁整頁落在 9–15px（章名 15、課名 12、眉標 10、序號 9），首頁同層級是 20–26px（mobile-03-learn.png 對 mobile-01-home-fresh.png）。
- 對局側板最外層包了一個 font-num，中文按鈕與狀態全變成點陣字，再被瀏覽器合成粗體（PlayView.vue:347-348；mobile-02-play-board-midgame.png 的「輪到你／悔棋／投降」）。Cubic 11 只有一個字重，14px 也不在它的 11px 格線上。
- 深青面沒有 token：main.css:293-331 有六組手寫的綠色漸層。對局頁一屏疊了四種綠（頂欄、頁底、側板、底部導覽），首頁那一屏沒有任何一個面是 #103029 原色。
- 首頁 y=296–700 之間同時有三條墨筆、旋轉的印框標籤、金環硬幣、點陣計數、面板光澤、雙劍浮水印、左粗邊卡。每樣都很淡，沒有一個當家。墨韻在 main.css:333-337 自稱全 app 共通，實際只出現在首頁和課程完成卡。
- ink-faint（#A88C76，米白上 2.6–3.0:1）被當成一般文字色，用在棋理卡說明、圖例、章節副標、對局紀錄日期。colors_and_type.css:80 自己註明這個色不得用於內文。
- 圓角 10 種、手寫陰影 25 種、動畫時長約 10 種；動效 token 只存在設計文件，沒進 @theme。

影響：全站，對局、學習、棋理三頁最明顯。

### 原因五：只做了主幹的正常狀態

邊界狀態、資料佔位、功能增刪後的殘留直接露在畫面上。每一項都小，但都在一定會經過的路上。

- 對局狀態列印出「Lv.0」，是 Stockfish Skill Level 的原始值；兩秒前彈窗裡選的是「初學」（PlayView.vue:406）。
- 對局紀錄每一列的粗體主標永遠是英文「Unknown opening」，因為寫入時兩個開局欄位固定寫 null（data-sync.ts:71-72；mobile-09-history-games.png）。
- 棋憶深青格走錯一手，棋子不會滑回。走錯的若正好是該將殺的那顆子，題目就解不了，只剩「看答案」（KeyMomentsCard.vue:119，部署站也重現）。
- 分析中的骨架是一大三小四塊灰塊，畫的是已經下架的清單版型；之後出現的是棋盤加一張對話框。手機上要看約 10 秒（mobile-10-review-analysing.png；MemoryDashboard.vue:52-65）。
- 深青面板左上的光澤有一條看得見的直邊，每一張面板都有（dark-panel.vue:16-17；mobile-01-home-fresh.png「開始新對局」卡左上、mobile-09-history-games.png 戰績面板）。
- 其他：0/21 的帳號看到「繼續 · 第 1 課」；同一個選單「紀錄」「記錄」混用；課程／棋理分頁的底軌用了沒進 @theme 的 token 所以透明；404 用 Unicode 棋子字元且多捲 96px；桌機判斷場棋盤撐到 968px，按鈕掉到摺線下。

影響：對局、對局紀錄、棋憶、學習、判斷場、404。

### 原因六：沒有一張「完成品長這樣」的圖，裁判文件也過期了

這是前五項的上游。

- README 描述的還是六月的產品：4–5 格 tab、關卡地圖、eval bar、Neve 無插畫（README.md:13、140）。當初拍板用的決策樣張在 2026-08-02 全刪了，main.css:376 還指向已刪的檔案。
- 文件裡的 token 有一部分沒進 @theme，所以 bg-surface-mid、rounded-pill 這種不存在的 class 可以無聲上線。
- 規則之間互相打架，沒有人裁決。動效上限 README.md:171 寫 400ms 加 2 秒呼吸，CLAUDE.md 寫 150–300ms；現有五處超標的動畫各自在註解裡宣稱例外（NeveSceneHeader.vue:93-95 的 620ms、LessonPlayer.vue:480 的 0.38s 回彈、DeepeningWrapUp.vue:93、main.css:365 與 PlayView.vue:505-521 的無限循環）。首頁那句 Neve 的話用明朝，人格檔規定她的話一律文楷並裝在對話框裡。README 規定棋譜 14px，又說 Cubic 11 設計在 11px 格線上。頂欄的「登入」連結違反「header 只放品牌與齒輪」（app-nav.vue:64-71）。

現有的鐵則只能擋掉錯的東西。要產生對的東西，得有一張能指著比對的樣張。

- ChapterBadge（真棋子剪影加金環）與 InkBrush（自己寫的向量筆觸）。兩個都是 Gambit 自己的圖形資產，目前用得太小。

- 完局卡的內容與優先序：Neve 署名、主按鈕導向回顧、文案平靜。
- 基本功：觸控目標幾乎全數 ≥44px、390 寬無水平溢出、多數自訂動畫只動 transform／opacity 並處理 reduced-motion、走子與對手思考的節奏、鍵盤基礎建設、返回鍵依來源決定去處。

## 5. Tally 那次為什麼有效，哪些能搬過來

看了 D:/Personal/Tally/DESIGN.md 與 _design-sample 底下的三份樣張。

流程上有效的做法，Gambit 都能照做：

1. 先有一句場景，再有一份用真 token 畫的樣張當真相來源。Tally 的方向段只有一段話（安靜的夏日午後，太陽是時間、踏腳石是四餐），樣張是 storybook-merged.html。Gambit 現在只有使用限制，沒有這兩樣。
2. 每次給 2–3 個並排的方向，用真實手機寬度畫，每個方向旁邊寫明代價與脆弱處，由使用者選或混搭。other-pages-directions.html 的 A／B／C 最後選的是「A 的橫幅加 B 的空狀態」。
3. 分批上線，每批可以獨立發布：v2.122 基礎與今日頁、v2.132 其他頁與空狀態、v2.133 App 圖示、v2.135 登入與全站狀態。
4. 保留版面與行為，只換畫面。版本紀錄寫著「舊 token 名一律保留、只換值」「產品既有的行為優先於樣張」。Gambit 上一次（垂直世界）是整個版面重來，每輪比較都輸給舊卡片版面，最後整個收案，什麼都沒留下。
5. 每批列出「我定的（可逆）」：實作時偏離樣張的地方與理由。
6. 把減法寫成文件。Tally 有「禁止事項」和「已否決的做法」兩張表，每條附理由。Gambit 在功能層刪得很兇（D1–D10），視覺層沒有這張表，所以每一輪潤飾都只加不減。
7. 真機回饋幾天內就修。v2.135 的起因是使用者自己說登入頁沒跟上改版。

畫面上可以搬的做法：

- 一幅畫用到底。Tally 的登入、開機、整頁錯誤共用同一幅畫（Gate.tsx），設定與訓練頁用 96px 的矮橫幅接上同一個世界。Gambit 的邊角狀態現在各用一個範本。
- 整頁一個聲音。Tally 砍掉 wordmark、宋體和點陣字，個性交給插圖與數字。Gambit 五種字體沒有一個當家。
- 骨架照真實列的高度畫，載完不跳版面，延遲 300ms 才出現。
- 空狀態只在「第一次、還沒有東西」時配圖，篩選結果與錯誤維持純文字。

不要搬的：

- 山坡與藍色。那是 Tally 的世界，v2.122 起它已經不跟 Gambit 同步。
- 「插圖同時是儀表」的因果。Tally 一天開五次、每次三秒，畫必須報資訊。Gambit 是坐下來下一盤，畫不必當儀表；硬把課程進度畫進首頁，會撞到定位 v2「對關卡與進度說不」。
- 2.1 秒的開場動畫，超出 Gambit 的動效鐵則。
- 全產品不出現 wordmark。Gambit 的鐵則是頂欄放品牌。

## 8. 候選方向

地基三個樣張都有，它本身不是選項。B 和 C 的描述已依找漏洞的結果修過：B 不做登入頁整頁直幅（閘門依定位要拿掉）、不讓畫報狀態；C 的印章對象是上一盤或進行中那一盤，不是課程。

### 地基：共用骨架（原提案 A）

不加任何新圖像，把現有語彙收齊。全站只有兩種頁：外框頁（米白內容加一條深青頂帶）與棋盤頁（深青底、木盤、Neve 對話框）。同一個返回鍵、同一個木框元件、同一個 Neve 對話框（淺卡與深青兩態，名牌一種）。首頁拿掉 96px 的空帶，加一列「上一盤」。對局側板去掉框中框，中文回黑體。

只做到這裡的結果：乾淨、一致，像一個完成的產品。「畫面上沒有主體」這個原因沒有解，首頁仍是深青頂帶加兩張卡。

### B：棋境一景

給 Gambit 一幅自己的畫，而且只畫一幅：夜裡一張木棋桌的一角。平塗向量，遠景是硬邊分層的深青，中景是斜向的桌緣和兩三排棋盤格，前景是兩三顆 Gioco 剪影棋子與影子，光從一側斜進來，時段只改光的方向與冷暖，不用品牌金。它出現在首頁頂帶、棋憶分析等待態、空狀態、404；對局頁不放畫，棋盤本身是主體。

風險：成敗全看這幅畫的品質，帶透視的棋盤與棋子很難畫好，畫得普通會比沒有更像半成品。平塗的桌緣在棋憶等待態會直接貼著照片木紋的 Wood12 木框，兩種畫法放在一起可能打架。工作量三者最大（四個時段乘上數種裁切），誰來畫、用什麼畫還沒定。

### C：木、紙、墨

不靠插圖，靠材質與排版當作者印記。把 app 當成放在棋桌上的一本棋譜冊：木是物件、米白是紙、墨是筆跡。同時是一輪減法。招牌元素有兩個，都是放大現有資產：InkBrush 從 12px 的底線升格成 40–64px 高的一筆，只出現在頁首；棋子剪影印章放大到 72–96px，當頁首印記與完局印。字體的使用範圍收成三個聲音：明朝（題詞與標題）、黑體（所有 UI 與按鈕）、文楷（只給 Neve）；Cubic 11 只留棋譜、座標、計數；Cinzel 只留字標。五個字族仍然都要載入。拿掉玻璃樣式、面板光澤、雙劍浮水印、墨氣下滲、印框旋轉。對局側板是一張記譜紙放在深青上；完局時紙上蓋一枚印，贏是金環，輸與和是墨色環，標題不染金。

風險：氣質偏靜、偏書卷，可能讀成筆記 app。要推翻幾個已拍板的決定（2026-06-09 的側板點陣字、2026-07-22 的印框與墨氣下滲、README 的 notation 14），需要逐項點頭。墨與印章如果又只做一成，結果會和現在一樣。
