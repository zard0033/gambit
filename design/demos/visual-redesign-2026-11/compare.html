現況與三個方向並排

每列是同一個畫面：最左是 app 現在的樣子（2026-11-17 截圖），右邊是樣張，最右一欄是推薦的混搭。圖是 iPhone 寬度（390）的截圖，這一頁雙擊就能開；要看細節點上方的方向名稱開樣張本身（樣張要 npm run dev 才載得到字型）。報告在 production/visual-review-2026-11-17.md，要你決定的事在同目錄的 decisions.md。

混搭（推薦）

骨架用地基；首頁頂帶與 404 用 B 的畫，對局側板與完局用 C 的記譜紙和印，棋憶用地基。所有畫面用同一份假資料。

為什麼
獨立評審逐張比過：單一方向都不夠，B 的畫和 C 的記譜紙各自在不同畫面最強。
不能同屏
B 的畫和 C 的大墨、C 的棋盤縮圖、B 的完局徽章。
還缺
B 的畫要有人手修；印只能留一種畫法。

地基

不加新東西，只把骨架收齊：兩種頁、一個 Neve 對話框、一個返回鍵、一個木框、一筆墨。

解決
五種長相的棋盤頁變成一種；對局側板不再是點陣字；首頁空帶拿掉。
沒解決
畫面上沒有主體。首頁還是深青頂帶加兩張卡。
定位
不是選項。B、C 都蓋在它上面。

B 棋境一景

地基之上加一幅畫：夜裡一張木棋桌的一角。只出現在首頁頂帶、棋憶等待、空狀態與 404。

解決
首頁有主體，一眼認得是 Gambit。
代價
畫要畫得好；四個時段乘數種裁切，工作量最大。
脆弱處
平塗的畫貼著照片木紋的木盤，兩種畫法放在一起。

C 木、紙、墨

地基之上不加插圖：首頁是一張扉頁（大題詞加一筆墨），完局蓋一枚棋子印，對局側板是一張記譜紙。

解決
讀得出作者，又不依賴新素材；同時是一輪減法。
代價
要推翻幾個已拍板的裝飾決定；首頁的深青變少。
脆弱處
墨筆是程式算的形狀，正式做之前要一筆真的手寫。

樣張是 Windows 上的 WebKit 截的，字重和 iPhone 實機有落差；選定方向後要在手機上再看一次。
