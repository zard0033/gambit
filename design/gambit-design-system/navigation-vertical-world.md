## 狀態

**設計已拍板，尚未開發。** `README.md`《Spacing & layout》節現行「底部 tab 為主導覽」描述的
仍是目前上線行為，尚未被取代——待本設計真正落地實作後才更新該行。

## 核心決策

**首頁／樞紐從「SaaS 卡片牆 + 底部 tab」換成一個可垂直滑動的沉浸世界**，取代 tab 在多個目的地
間切換的心智模型。範圍：**只換首頁樞紐與跨場景轉場**，滑進去之後的實際功能頁（課程內容、
真正下棋、棋誌內頁）維持現有正常頁面，不整頁沉浸化。

### 空間語意（不可反轉）

垂直軸的上下有固定意義，不是任意排序：

- **上＝沉澱、回望**（棋誌）
- **中＝當下**（對局／首頁預設落點）
- **下＝深處、挑戰**（試煉／dungeon）

Demo 驗證用五層（棋誌／課程／對局／棋憶／試煉）由上到下排列；正式落地前需要對照完整
IA 盤點決定其餘目的地怎麼併入這條軸（本檔只鎖空間語意方向，不鎖最終是否就是這五層）。

### 導覽：右側旅程軸（取代底部 tab bar）

- 固定在螢幕右緣的一條細墨線，串起每層的小 icon（**直接重用該層中央本來就有的 glyph**——
  書／學士帽／棋盤格／時鐘／拱門，不新發明一套 icon 語彙）。
- 當前層 icon 變 `--color-accent` 金色＋柔和呼吸光暈（約 2.6s 循環）；其餘層維持
  `--color-ink-faint`。點擊任一 icon 平滑捲動到該層。
- Label 文字預設隱藏、當前層才淡入顯示在 icon 左側。
- **已測試並否決的方向**（別重做）：數字座標尺（借棋盤 rank 編號視覺）、連續深度計指針
  ——兩者都被判定「看起來很醜」，比原本簡約的圓點更差。教訓：**加法不等於加分**，加裝飾
  元素（數字、標尺線、額外指針）比換成有意義但依然簡約的 icon 更容易顯得雜亂。

### 動效詞彙

| 元素 | 行為 | 參數 |
| --- | --- | --- |
| 捲動吸附 | 每層強制停（`scroll-snap-stop:always`），大力滑最多走一層 | ⚠️ 未在真機驗證，見下方待驗證 |
| 天空漸層 | 隨捲動位置連續內插相鄰兩層的頂/底色，不分段跳 | linear-gradient，逐幀重算 |
| 星塵密度 | 隨捲動位置連續內插相鄰兩層的目標密度，指數平滑趨近 | 3 層景深（近/中/遠），各自呼吸閃爍＋自然上飄＋捲動視差＋捲動慣性餘韻 |
| 進場節奏 | 每層 depth-tag／icon／標題／內文依序上浮淡入 | delay 0.04s→0.12s→0.22s→0.32s，700ms，`cubic-bezier(.2,.7,.2,1)` |
| 前景視差 | 每層內容隨捲動位置微幅位移，製造景深剝離感 | `translateY` ∝ 與視窗中心的層距 |
| 環境墨霧 | 兩團模糊的 jade 光暈緩慢飄移 | 26s／34s 循環，`mix-blend-mode:screen` |
| 呼吸光 | 首頁層地平線光帶、試煉層底部火光 | 5–6s 循環 radial-gradient 呼吸 |

全部動效必須尊重 `prefers-reduced-motion`：關閉自走循環（星塵自飄、墨霧飄移、呼吸光、
icon 脈動），進場內容直接可見不跑 transition，捲動改 `scroll-behavior:auto`。

### 落地優先序（CLAUDE.md「樣式落地優先序」規則已生效）

真開發時，上表的「行為」是要保留的決策，「怎麼寫」要重新按階梯選：

1. 版面/間距/置中 → Tailwind utility class。
2. 顏色 → 既有 `var(--color-*)` token（深墨綠主題已有 `surface-deep`／`accent`／`ink-faint`
   等，不用新增）。
3. 星塵 Canvas、捲動視差、呼吸光暈、進場 stagger → 這些是 utility 表達不了的複雜視覺，
   屬於規則第 4 級允許的例外（動效／複雜佈局），可用 scoped `<style>` 或抽成 composable，
   **但要在上方註明理由**（例如「canvas 逐幀渲染星塵，utility class 無法表達」）。

## 已知待驗證 / 未鎖定事項

- **捲動吸附跨格**：桌機滑鼠/觸控板測試仍會跨兩層，但那個輸入物理跟 iPhone 觸控 fling
  不同，桌機測不準。**➌ 真機（iPhone Safari）務必重驗**；若仍跨格，需要 JS 攔截捲動
  （比 CSS 重的做法，屆時再評估要不要做，不預先假設需要）。
- **旅程軸 tap 目標**：demo 的 button 只有 `min-width:44px; height:30px`，**高度不足
  44px 觸控底線**（CLAUDE.md 硬性要求）。真開發時用 padding 撐大命中區，icon 本身可以
  維持視覺上的小巧。
- **focus-visible**：demo 沒做鍵盤焦點樣式。真開發必須補 2px 金色 focus ring（既有
  design system 規則），旅程軸 icon 按鈕不能漏。
- **五層是否為最終導覽全集**：demo 只驗證了空間語意與動效手感，沒有對照完整 IA 盤點；
  真正還有哪些目的地要掛在這條軸上、或是否還需要一個「更多」出口，落地前需要另外盤點。
